# Research-to-delivery lead time

Part of the [delivery-process retrospective](retrospective.md) method in the [continuous-improvement operating model](../continuous-improvement.md#routed-topics); a formal retrospective reads every retrospective topic.

Every retrospective also reports how long decided work waits before it lands. The analyzer computes it over the exact PR window as `researchToDeliveryLeadTime`, listing each pull request or issue used with its elapsed days, plus the count and median of each measure:

- **handoff to merge** — for each implementation pull request merged in the window that implements a research [implementation handoff](../researching.md#implementation-handoff), the time from the handoff's commit date to the merge;
- **issue opening to merge** — for each issue closed in the window by a merged pull request, the time from the issue's opening to that pull request's merge;
- **open issue age** — for each issue still open at the end of the window, its age at the through PR's merge. An issue a window pull request closes is measured as closed, not open, even when GitHub records the close seconds after the window ends.

Each implementation pull request names its input: the issue it closes and, when that issue cites a research implementation handoff as supporting evidence, the handoff on the standalone `Implementation handoff:` line the [Implementer](../agent-roles/implementer.md#pull-request-and-ci) defines. Acquisition confirms each named handoff's commit, file and commit date against GitHub. An issue counts as closed by a pull request only when GitHub records that pull request as the closer of the issue's current closure; a link saying a pull request may close an issue is not closure. An issue closed in the window any other way appears in neither measure. Whether an issue was open at the end of the window comes from its current opening and closing times, not its close and reopen history. The `Implementation handoff:` line and its `handoff to merge` measure are retained executable behavior: the evidence contract treats the handoff reference as optional (`null` when the PR names none), so it records a research handoff that an admitting issue cites as supporting evidence and does not treat that handoff as an admission route or require it. These are measures to compare between retrospectives, not targets or thresholds.
