## 3. Contract, failure-model, oracle and technique matrix

### Interpretation of the matrix

IDs are semantic names local to this assessment, not new product IDs or durable tracking labels. Each row covers the entry-point types and their supporting records/enums/exceptions in the crosswalk. For those values, include constructor null/empty/invalid combinations, collection/array defensive copying, equality/hash consistency and mutually exclusive success/failure representations wherever the existing value contract defines them. Do not impose stronger validation on intentionally invalid drafts or make arbitrary null misuse a supported runtime command.

Priority is qualitative: **critical** means false authority, silent accepted-state corruption or deterministic semantic drift with poor immediate observability; **high** means a public result/refusal can be wrong but is more locally observable; **supporting** means localized value/static guard or non-shipped evidence integrity. Exposure (untrusted bytes, public commands, internal-only states), interacting state/branches and observability explain each assignment. They are not numeric confidence or mutation thresholds.

Technique codes are fully specified in §4: B boundary/finite enumeration; P property/metamorphic; M targeted mutation; L bounded state/model exploration; J structured grammar generation; I failure injection; A static/integration checks. A row passes its **future campaign** only if its listed relations and refusals hold, relevant mutants are killed or explained, and every failure family has evidence or an explicit blocker. Nothing here is a runtime pass.

## 4. Experiment portfolio and concrete execution recipes

These are **proposed Phase B experiments**, not instructions to start them now. Every family uses source/model/script bytes as the primary replay identity, not a random seed alone. Retain generator version, seed/PRNG where used, size bounds, input enumeration order, environment/tool versions, exact assessed SHA, source mutations, selected tests/counts and actual verdict. Save the original and minimized failing input. A minimized input is useful only while it still satisfies the relevant preconditions or preserves the intended malformed class.

### B — deterministic finite and numeric boundary enumeration

Entry points: value constructors/parsers, `FactoryModelPublisher.publish`, `FactoryModelArtifact.decode/fingerprint`, `ConformanceEvaluator.evaluate`, `EvidenceConformanceEvaluator.evaluate`, Challenge validators/calculators/policy/comparator. Generate explicit partitions above; compute independent expected values with BigInteger, tuple sets, literal byte tables and authored truth tables. A pass means exact value/diagnostic/refusal AND required post-state, not absence of an exception. For finite guards enumerate all combinations, recording unreachable combinations and why constructors prevent them. Pairwise is adequate only for independent predicates; authority-role-subject and dispatch-capacity-eligibility require higher-order combinations. Shrink toward adjacent thresholds, fewer records and one violating predicate while retaining a second interacting predicate when causal. Plain JUnit loops suffice; no property library needed. Small truth tables are tens to thousands of cases; ASCII-escape single-position sweep is exactly 262144 cases. Full 4-character UTF-16 Cartesian enumeration is not feasible or required: independent membership checking at each position plus interactions of legal/illegal positions is the justified decomposition. Timing is unknown until calibrated.

### J — grammar-aware generation, not arbitrary crash hunting

Binary entry: FactoryModelArtifact; JSON entry: package-local Json plus public ChallengeContentLoader load/catalogue/combined entry points. Seed corpus: current literal golden models, zero/minimal records, astral and combining text, optional null/finite/signed-zero/NaN, reordered eligible sets; JSON valid minimal challenge/catalogue and scalar grammar partitions. Build a small test-local encoder from F §4 that does not call canonical helpers; first validate it against literal vectors, then generate valid inputs and mutate one labeled field. Enumerate each truncation offset for small artifacts; length/count mutations include 0,1,remaining±1,int boundary,negative/high-bit long; malformed UTF-8 includes overlong, lone continuation, surrogate encoding and truncated multibyte. Combine canonical-but-invalid publication content, unsorted/duplicate eligibility, alternate NaN payloads, unsupported prefix and trailing bytes. Oracle: exact independent bytes and decode model for valid cases; explicit refusal/no partial artifact for invalid cases. For JSON use an independently authored ASCII token table; a third-party parser can be a secondary comparator only on a documented intersection (numeric representation, duplicate keys, surrogate handling may differ). Never vote by majority of parsers.

Minimize syntax tree/field first, bytes second, retaining failure class. Reproducer contains exact bytes/hex or escaped UTF-16, entry point and expected structured issue; avoid text transport normalizing the reproducer. Bound document size/depth/heap/time in the diagnostic process and report a resource cap as **inconclusive**, not a decoder refusal. Unknown feasibility: no fuzzer installed or JVM fuzzer integration tested. JUnit systematic generators are the minimum viable tool; optional coverage-guided fuzzing requires a temporary separately recorded setup. A retained diagnostic crash does not automatically establish an unsupported OOM/stack-depth product guarantee.

### L — stateful model and bounded exhaustive exploration

Scheduler model: sorted list of `(time,insertionOrdinal,distinctPayload)` plus current time, no PriorityQueue or Scheduler comparator reuse. Enumerate schedule valid/equal/past, peek and dequeue for traces initially up to length 6 over three time values and three distinguishable payloads. Report exact state/transition counts, omitted long-range limits and branch pruning. A longer seeded sequence extension covers sizes without pretending bounded enumeration is universal.

Engine model: independent small transition relation derived from E §§1.2–4, using explicit lists of waiting/active jobs and a declarative lexicographic selection tuple. Start with 1–3 resources, capacity 1–2, 1–3 children and steps, times/durations 1–3, overlapping/disjoint eligibility and offline states. Enumerate bounded command scripts including no-op/rejected availability, workload, step/bounded advance, capture/drain and reset. Validate the reference model on distinguishing hand-derived fixtures before comparing production. Compare accepted/rejected/faulted outcomes, assignment, ordering, simulated time, aggregate values and event/observation boundary after **every** transition. The model must explicitly implement local-one/shared-fixpoint behavior; “sensible scheduling” is not this specification. Overflow/cascade-fault traces use separate symbolic extreme values; do not explode the small state space by mixing all 64-bit values.

Governance model: append-only accepted revision/reference/occurrence ledgers; enumerate accept/redeliver/rebind/correct/use with 2–3 IDs, same/different fingerprints and definitions. Observe all authorities before/after refusal. Research model: independent interval-set coverage with basis/frontier and gaps, not merely contiguous list checking. Shrink by deleting commands and reducing resources/jobs while replaying preconditions; record failed reductions. Use ordinary JUnit breadth-first traversal and visited-state keys written independently. A formal model checker is optional, not presumed installed; bounded executable exploration supplies a feasible no-new-tool route. State explosion is explicit: stop at a declared state/heap budget, record frontier, reduce unrelated dimensions and retain higher-order witness families; a truncated run cannot close that family. Exact 64-bit exhaustion is replaced only by a stated arithmetic invariant/proof, never a claimed exhaustive test.

### P — properties, metamorphic relations and limited differential checks

Apply only contract-licensed transformations: eligible-set insertion order, input collection copies, Challenge occurrence permutations, repeated identical scripts with new RunId, partitioned advancement preserving the same effective command times, exact same-binding reopen, and reversing compatible comparisons. Factory top-level lists are **not** permutation-invariant; machine-ID renaming is not outcome-preserving when it changes tie-breaks. Capacity increase does not generically imply better makespan under all dispatch interactions, so no unjustified monotonic-performance oracle. Metadata-only capacity/setup changes preserve current execution but change fingerprint/configured observations. A test must normalize only fields the contract excludes (RunId for semantic replay; expected metadata/fingerprint differences for that specific transformation).

Independent alternatives available: small list scheduler, specification byte encoder, finite dispatch model, BigInteger arithmetic, tuple/interval sets, hand-integrated occupancy. Correlated alternatives: advance versus advanceUntil, encode versus decode using shared canonicalization, replay via same runner, two occupancy derivations sharing ProcessingIntervals, evaluator-based comparison fixtures. Use the latter as consistency checks with complementary independent goldens/models; never call them independent differential validation. Shrink transforms as a pair so the relation remains admitted. Plain JUnit plus a fixed explicit seed list is sufficient; property frameworks with shrinking are optional after feasibility measurement.

### M — targeted assertion fault sensitivity

For each row, mutate the named guard/field/order/arithmetic/publication point independently. Minimum control: compile and run selected tests unmodified, verify nonzero expected test discovery, then compile exactly one mutation and rerun identical selection/environment. An invalid compilation is not a killed semantic mutant. Save mutation diff, source hash, killer assertion or survivor reproducer. Inspect survivors for semantic relevance, reachability, equivalence or missing oracle. A test killed merely by setup failure does not prove the intended invariant. Hand-edit isolated copies/temporary worktrees or build inputs under logs; never leave production mutants in an implementation commit. PIT may later automate suitable operators, but neither its installation nor compatibility is assumed. No numeric mutation threshold.

Cost scales as number of valid mutants × focused test time; initially single digits to a few dozen meaningful mutants per boundary, selected by all enumerated failure families rather than a fixed quota. The historical Scheduler probe supplies a control design, not current measured runtime. Complement mutations with generation/model checks: selected operators cannot represent every serious fault. Completion is explained sensitivity of each meaningful proposed fault family, not a score.

### I — deterministic acceptance, failure and reopen experiments

Oracle is a small commit-point state machine: revision absent before install; potentially accepted after install; referenced artifact never deleted. Do not assume caller exception means rejection. Two-thread schedules use latches at known seams, bounded joins and captured exceptions, and check one immutable winner for conflicting ID. No arbitrary sleeps as ordering proof.

Engine injection uses published extreme-duration models and normal commands to reach real late cascade overflow; verify all authoritative partial effects and outgoing events after the fault. Do not change runtime semantics or replace errors with a test-only transition. Failure fixtures must distinguish pre-mutation rejection from post-mutation failure. Tool cost includes process/filesystem startup and all stage combinations; expected thousands rather than billions of small operations, actual duration unknown.
