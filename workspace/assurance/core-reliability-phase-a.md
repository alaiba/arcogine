## 3. Contract, failure-model, oracle and technique matrix

### Interpretation of the matrix

IDs are semantic names local to this assessment, not new product IDs or durable tracking labels. Each row covers the entry-point types and their supporting records/enums/exceptions in the crosswalk. For those values, include constructor null/empty/invalid combinations, collection/array defensive copying, equality/hash consistency and mutually exclusive success/failure representations wherever the existing value contract defines them. Do not impose stronger validation on intentionally invalid drafts or make arbitrary null misuse a supported runtime command.

Priority is qualitative: **critical** means false authority, silent accepted-state corruption or deterministic semantic drift with poor immediate observability; **high** means a public result/refusal can be wrong but is more locally observable; **supporting** means localized value/static guard or non-shipped evidence integrity. Exposure (untrusted bytes, public commands, internal-only states), interacting state/branches and observability explain each assignment. They are not numeric confidence or mutation thresholds.

Technique codes are fully specified in §4: B boundary/finite enumeration; P property/metamorphic; M targeted mutation; L bounded state/model exploration; J structured grammar generation; I failure injection; A static/integration checks. A row passes its **future campaign** only if its listed relations and refusals hold, relevant mutants are killed or explained, and every failure family has evidence or an explicit blocker. Nothing here is a runtime pass.

## 4. Experiment portfolio and concrete execution recipes

These are **proposed Phase B experiments**, not instructions to start them now. Every family uses source/model/script bytes as the primary replay identity, not a random seed alone. ### B — deterministic finite and numeric boundary enumeration

Entry points: value constructors/parsers, `FactoryModelPublisher.publish`, `FactoryModelArtifact.decode/fingerprint`, `ConformanceEvaluator.evaluate`, `EvidenceConformanceEvaluator.evaluate`, Challenge validators/calculators/policy/comparator. Generate explicit partitions above; compute independent expected values with BigInteger, tuple sets, literal byte tables and authored truth tables. For finite guards enumerate all combinations, recording unreachable combinations and why constructors prevent them. Timing is unknown until calibrated.

#### Extreme cursor oracle and controls (A2 / U10; proposed B/L/M design)

Entry points: `EvidenceWindow.missingWithin`, `isComplete`, and package-appropriate `DeclaredEvidence.completeEvents` through a declared oracle. Separate a legal-shaped helper record from a runtime-produced capture. Let query be `(a,b]`, final cursor `f`, and declared closed gaps `G`, with 0 <= a <= b <= MAX and valid positive gap endpoints. Expected missing set is exactly `{s : a < s <= b and (s > f or s belongs to G)}`. Do not infer event objects from window metadata alone.

Implement the independent oracle as open/closed endpoint pairs: if a=b return empty immediately; intersect each gap with query by comparison; add post-frontier pair `(max(a,f),b]` only if b>max(a,f). Union/normalize expected ranges by endpoint order. No f+1 sentinel exists. A closed output low may be computed as x+1 only after proving x<high<=MAX (or with BigInteger and checked narrowing); gap-to-pair conversion g.low-1 is safe only for g.low>=1. Do not call SequenceRange intersection/completion helpers, production missingWithin, or iterate to MAX. Compare set membership and reported endpoints; preserve duplicate/overlapping returned ranges as discrepancies for triage rather than silently normalizing away their cause. Do not invent an ordered-normal-form API guarantee where the helper promises only missing sequences.

#### Governance shortcut oracle ordering

Use two independent truth tables rather than a universal malformed-binding rule. Structural evaluator: mismatched assertion, supplied state fingerprint or optional accepted revision refuses even with disjoint impact; valid subject plus disjoint impact gives NOT_APPLICABLE; applicable external-evidence-required assertion or absent structural state gives UNKNOWN; sufficient structural state invokes its assertion and yields PASS/FAIL. Refusal here is input/authority failure, not a real-world FAIL.

Evidence evaluator: pairing/optional subject revision and basic value/null preconditions first; valid subject plus disjoint scope gives NOT_APPLICABLE without reaching evidence-kind or use validation. Within applicable/unfiltered scope, structural-only assertion refuses this evidence-composition API; malformed exact-definition/target/revision use refuses; adequate relied-on use allows the supplied judgment, whereas supplied PASS/FAIL with only excluded/comparator/no adequate use becomes UNKNOWN. A supplied UNKNOWN remains unresolved. Public EvidenceJudgment itself excludes supplied NOT_APPLICABLE; scope owns that result. Verify the full attribution, findings only for FAIL, and intersection versus full-scope mode. H §6 permits malformed input rejection but supplies no requirement to move every use check ahead of scope. Tests must distinguish these paths without calling evaluator/assertion code as their expected-result oracle.

### P — properties, metamorphic relations and limited differential checks

Apply only contract-licensed transformations: eligible-set insertion order, input collection copies, Challenge occurrence permutations, repeated identical scripts with new RunId, partitioned advancement preserving the same effective command times, exact same-binding reopen, and reversing compatible comparisons. Factory top-level lists are **not** permutation-invariant; machine-ID renaming is not outcome-preserving when it changes tie-breaks. Capacity increase does not generically imply better makespan under all dispatch interactions, so no unjustified monotonic-performance oracle. Metadata-only capacity/setup changes preserve current execution but change fingerprint/configured observations. A test must normalize only fields the contract excludes (RunId for semantic replay; expected metadata/fingerprint differences for that specific transformation).

Independent alternatives available: small list scheduler, specification byte encoder, finite dispatch model, BigInteger arithmetic, tuple/interval sets, hand-integrated occupancy. Correlated alternatives: advance versus advanceUntil, encode versus decode using shared canonicalization, replay via same runner, two occupancy derivations sharing ProcessingIntervals, evaluator-based comparison fixtures. Use the latter as consistency checks with complementary independent goldens/models; never call them independent differential validation. Shrink transforms as a pair so the relation remains admitted. Plain JUnit plus a fixed explicit seed list is sufficient; property frameworks with shrinking are optional after feasibility measurement.

### M — targeted assertion fault sensitivity

For each row, mutate the named guard/field/order/arithmetic/publication point independently, including the five U10 endpoint controls and Governance shortcut-order controls above. Minimum control: compile and run selected tests unmodified, verify nonzero expected test discovery, then compile exactly one mutation and rerun identical selection/environment. An invalid compilation is not a killed semantic mutant. Save mutation diff, source hash, killer assertion or survivor reproducer. Inspect survivors for semantic relevance, reachability, equivalence or missing oracle. A test killed merely by setup failure does not prove the intended invariant. Hand-edit isolated copies/temporary worktrees or build inputs under logs; never leave production mutants in an implementation commit.
