## Revision of the challenge findings

### CH-1: independent complete diagnostic observations

`Campaign1DiagnosticOracle` maps the independently derived predicate violation list to literal
field/message strings. Every one of the 100 single-predicate/boundary cases and 4,096 toggle
combinations compares the **entire ordered sequence**, not a kind multiset alone. Publisher refusal
type and payload are checked against that expectation. The eight fresh JVMs compare 111 compound
models (masks 0 through 4095, step 37) plus the signed-ID witness with independent expectations;
expected sequences no longer come from another validator invocation. The 720 signed eligible-set
permutations remain. The prior literal nine-diagnostic witness is also executed.

Only signed eligible-resource order is normative here. Other sequence and message assertions
deliberately pin observed baseline behavior to make changes visible. A wording-only mutant is a
successful observation control, not evidence of a specification violation.

### CH-2: exact Storage refusal and post-state

The campaign seam now checks exact `GovernanceHistoryException` and distinguishes
`FINGERPRINT_MISMATCH`, `UNSUPPORTED_ARTIFACT_FINGERPRINT`, and `MISSING_REVISION`. After each
failed acceptance it checks absence of that candidate ID, unchanged revision enumeration, and
unchanged historical base bytes. The original four-artifact seam uses a nonempty published model;
the reused independent four-artifact witness adds the empty-model boundary and exact snapshot
exception-class checks. No broad `RuntimeException` catch remains in the producer seam.

These observations cover malformed/trailing bytes, wrong digest, foreign namespace and absent
revision under the real authority. They do not close every Storage category, arbitrary disk failure,
crash atomicity, cross-build reopening or historical compatibility.

### CH-3: every authored operation

The 500-model assembly loop now resolves every authored operation directly by ID and compares
name, routing ID, ordered step IDs/names/durations and eligible members. Product-to-operation
mapping is checked separately. The generator deliberately rotates original, zero-product and
at-most-one-product variants, retaining unreferenced and partially referenced operations. Resource
facts, product IDs, observation order, session isolation and metadata behavior remain checked.
The minimal one-operation/zero-product witness is retained. The direct lookup fixes the observation
gap without making product membership the oracle for operation existence.

### CH-4: byte frontier and mutation classification

The old method name `exhaustiveSingleEditCorpusAgreesWithTheIndependentDecoder` is preserved to
keep the corpus/test identity recognizable, but **does not mean all byte values**. Its actual
8,489 attempts over 47-, 297- and 481-byte fixtures use truncations, deletions, up to six chosen
replacement values and three insertion values (`00/01/ff`). Attempts contain duplicates. The
reported 1,295 accepts are attempts, not distinct cases. Untried single-edit values remain outside
that corpus (including representative byte 47 `4d` → `41`), alongside compound edits and large
allocation boundaries.

The additional empty-grammar witness alone exhausts 11,985 nonidentity replacements and 12,288
insertions over all 256 values and checks exact `IllegalArgumentException`. That fixed 47-byte
grammar result must not be generalized to populated models. Three original vectors plus the
190-byte signed/Unicode literal witness pass. `oracles/canonical_vectors.cjs` independently
frames the values with Node big-endian integer/binary64/UTF-8 operations and SHA-256; its field
offset/hex derivation is retained in `results/rederived-vectors.json` and matches the three Java
literal constants. It does not call product canonicalization or the Java oracle.

`classify.cjs` rejects empty/failed baselines, changed discovery, compile failures, suite/test
errors, skips, missing/inconsistent exits and timeouts as inconclusive. Ordinary assertion failures
remain **assertion-detected pending semantic triage**, not automatic kills. Unexpected exceptions
also require triage. Twelve synthetic controls exercise these paths, including the discovery-error
counterexample that broke the old ledger. Actual run records and the separate triage table preserve
this distinction; no compilation/discovery failure is silently counted as a semantic kill.

No compile/discovery failure or timeout occurred in these 47 runs. Five automatic inconclusive

## Discrepancies and next responsibility

No unmodified-product violation was confirmed. CH-1 and CH-2 were observation gaps; CH-3 was an
assembly coverage gap; CH-4 was overbroad wording and fail-open classification. The revised sources,
controls and limits address them for the bounded packet; **a separate challenger must decide
whether they are sufficiently addressed**. Original D1 observation order, D2 decoding/publication
separation, D3 invalid helper fixtures and D4 detail parsing remain experiment assumptions/errors,
not production fixes. D5 fingerprint rendering remains a qualified observation without a parser
requirement. Missing original intermediate failure records cannot be reconstructed.

During this revision the Node cross-check initially rejected its own extraction regex because the
empty Java constant spans two lines. Whitespace handling was corrected before the successful
derivation. This was tool/fixture parsing, not a product discrepancy or mutation kill. Its minimized
cause is `EMPTY_HEX =` followed by a newline; no golden value was changed.

No maintained product source, test or specification changed. No new retained regression is proposed:
the three prior regression assertions are already on the pinned main. Full `./arcogine check`,
security scans, coverage and exact-head `CI / gate` were not run for this transient evidence-only
publication; no implementation PR or merge-readiness claim is made. Those omissions are not a
partial pass disguised as a full contribution gate.

Next owner action is targeted independent follow-up of this exact packet, especially complete
diagnostic independence, the Storage codes/post-state, unreferenced operations, byte scope and
mutation triage. Keep issue #541 open. Final-main reconciliation, other campaigns, authorized Phase C

## Reproduction

Use a fresh detached checkout of the exact baseline and a supported JDK 21. Keep all experiment
overlays and mutants in that scratch checkout. From this directory run, in order:

```powershell
./run.ps1 -Source <scratch-checkout> -Jdk <jdk21-directory> -Stage baseline
./run.ps1 -Source <scratch-checkout> -Jdk <jdk21-directory> -Stage corpus
./run.ps1 -Source <scratch-checkout> -Jdk <jdk21-directory> -Stage mutants
./run.ps1 -Source <scratch-checkout> -Jdk <jdk21-directory> -Stage restored
node classify.cjs
node inventory.cjs
node oracles/canonical_vectors.cjs
node audit.cjs
```

Run against a copied evidence directory if preserving these exact results. The script invokes the
wrapper directly, observes its actual exit and restores each mutated source in `finally`. The
seven selected experiment/witness classes contain 43 tests; the retained baseline selection is
separate. `mutation/mutants.txt` contains the 44 original exact substitutions; `run.ps1` adds the
three challenge controls explicitly. Corpus text ledgers are generated by the final restored run;
each earlier invocation has its own complete XML and `run.json`, rather than claiming the shared
text-output directory preserved every intermediate ledger.
